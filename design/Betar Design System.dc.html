ROUND 1 · WHAT THIS IS
The system proposal: four themes, type scale, shape language, mesh ribbon, and the component specs the brief calls out. Plus one screen from each of the five destinations so the system can be judged in place, and the emergency flow as a working prototype.
ASSUMPTIONS I MADE
  • Reference frame 360 × 800 dp, body base 18sp.
  • Logo geometry taken from the brief (bars 20–46 / 62–88); the uploaded file uses a narrower wire — flag which is canonical.
  • Bengali / Hindi UI strings shown as marked slots bn.chats until you supply them.
  • Pictograms are labelled placeholders; the shape silhouette carries the meaning today.
RULES I AM HOLDING
  • Red is emergency only. Errors and warnings are amber.
  • No ticks. Delivery is a mesh glyph that gains nodes.
  • Every state carried by two of: colour, shape, pictogram, text.
  • No network language. No security jargon. Nobody named.

06 · EMERGENCY FLOW · WORKING PROTOTYPE
Tap through it. Category, then detail with location off by default, then a deliberate slide to send, then live counters from the relay engine. Nothing here claims delivery.
{{ prototype }}
Why a slide, not a button
A button in a pocket sends. A 200dp horizontal drag does not. The gesture is one handed, works with wet fingers, and the track is 72dp tall. Voice-over reads it as a button with a confirm step for anybody using a screen reader.
What the status screen may say
carried by N phones nearby
N people have acknowledged
still looking for phones nearby
Never "sent", never "delivered", never a tick. Counters come from the relay engine and can go down as phones move away — that is honest and the copy says so.
